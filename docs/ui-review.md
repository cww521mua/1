# UI 走查与优化建议

> 审查方式：浏览器实测（登录/注册/概览/移动端 375px）+ 全部视图与布局代码走查。个别浏览器观察与代码核实有出入的条目已标注「待复核」；其余条目均定位到具体文件。建议按优先级实施，标注 ✦ 的是低成本高收益的「快速胜利」。

## 一、总体评价

- **布局层工程质量高**：[DefaultLayout.vue](../web/src/layouts/DefaultLayout.vue) 处理了吸顶页头测量、滚动条占位补偿、底部悬浮导航的安全区（`env(safe-area-inset-*)`）与内容让位，移动端底部留白也按导航高度预留，这些细节大多页面不需要再操心。
- **设计 Token 体系成熟但存在双轨**：`var(--ui-*)` 体系有 585 处使用（登录页、侧栏、活动中心、好友等成熟页面），但仍有 44 处手写 `dark:bg-gray-800` 类灰色调色板散落在 12 个文件里，两套写法混用导致深浅色观感不完全一致。
- **空状态组件已统一但未全覆盖**：[EmptyState.vue](../web/src/components/ui/EmptyState.vue) 在农场/背包/好友/商城等面板有 30+ 处标准用法，但新加的推广页、卡密面板、用户面板仍是手写居中图标+文字。
- **信息架构**：桌面端侧栏 9 项尚可；移动端底部导航只放 5 项，其余页面依赖侧栏抽屉，新增的「推广」入口在移动端可发现性弱。

## 二、问题清单

### P1 —— 优先处理

**1. ✦ 空状态写法不统一**
- 现象：[Referral.vue](../web/src/views/Referral.vue)、[CardKeyPanel.vue](../web/src/components/settings/CardKeyPanel.vue)、[UsersPanel.vue](../web/src/components/settings/UsersPanel.vue)、[Settings.vue](../web/src/views/Settings.vue)（账号 tab「暂无账号」）使用手写 `py-12 text-center` 块；其余面板统一用 `<EmptyState>`（自带图标/标题/描述/error 语气/bare 模式）。
- 建议：全部替换为 `EmptyState`，无账号的空状态补「立即添加」动作按钮（`EmptyState` 已支持默认插槽）。

**2. ✦ 移动端触达性：底部导航缺 4 个页面**
- 现象：[MobileBottomNav.vue](../web/src/components/MobileBottomNav.vue) 固定 5 项（概览/个人/活动/商城/设置），`好友 / 分析 / 节令日历 / 推广` 在 <1024px 只能通过侧栏抽屉进入，新用户难以发现。
- 建议：底栏保持 5 项不变，把抽屉触发按钮做得更明确（汉堡图标+「菜单」文字），或在底栏第 5 项改为「更多」聚合成底部抽屉（半屏面板列出全部页面）。移动端是买卡用户的主场景，值得做。

**3. 设置页 Tab 过多且在窄屏挤压**
- 现象：超管视角设置页有 7 个 Tab（账号/策略/自动控制/系统/卡密/用户/推广——推广虽是独立页但风格与 Tab 无异）。375px 下 NTabs line 模式横向滚动，靠后 Tab 触达差；且 [Settings.vue](../web/src/views/Settings.vue) 已约 2200 行，7 个 Tab 挤在一个组件里。
- 建议：
  - 短期：移动端把 Tabs 收进顶部下拉选择器（或左右滚动加渐隐遮罩提示可滚动）。
  - 中期：按功能把 Settings 拆为独立路由页（账号/策略/系统 + 超管的卡密/用户），侧栏直接给入口，去掉二级 Tab 的长滚动。

**4. ✦ 图标按钮缺少可达的提示与无障碍标注**
- 现象：账号卡片与卡密列表的操作按钮（设置/编辑/删除/复制）都是 `title` 属性 + 纯图标；`title` 在触屏无效，读屏也不稳定。
- 建议：统一补 `aria-label`；移动端长按或改用带文字的紧凑按钮；删除类操作已有 ConfirmModal 兜底，保留。

**5. 卡密页批量操作条不吸顶**
- 现象：卡密列表较长时，勾选卡密后顶部「复制选中/批量删除」按钮随页面滚出视野，选中数量不可见。
- 建议：选中数 >0 时把操作条吸顶（复用 `--sticky-top` 机制）或变为底部悬浮条，与现有吸顶体系一致。

### P2 —— 计划处理

**6. 深浅色双轨制收敛**
- 现象：44 处 `dark:bg-gray-800`（ConfigManage 12、Friends 7、Settings 4、Analytics 4、新面板 9、其余 8）与 `--ui-*` Token 混用；灰阶与主题灰在部分背景下有色差。
- 建议：给 `--ui-surface` / `--ui-ink` 系列 Token 补齐语义变体，逐步替换；先从新写的 3 个面板开始（工作量最小，也避免继续扩散）。

**7. 登录注册表单在手机上过长**
- 现象：注册模式（卡密+推广码）共 6 个字段 + 3 段提示文字，375px 下首屏看不到提交按钮。
- 建议：提示文案折叠为「说明」可展开项；推广码字段在无 ref 参数时收进「有邀请码？」展开项，减少默认高度。

**8. 空实例引导（首次部署观感）**
- 现象：全新部署时概览无账号、农场/背包/好友全部是「请先选择账号」空态，用户需要自己发现「设置 → 添加账号」。
- 建议：概览页在 `accounts.length === 0` 时展示一个引导卡（三步：添加账号 → 选择登录方式 → 启动），带直达按钮。`Dashboard.vue` 已引入 EmptyState，成本很低。

**9. 前端字段级校验增强**
- 现象：用户名规则（3-32 位、字母数字下划线）、卡密 16 位格式目前主要靠后端返回错误。
- 建议：登录页注册表单已有 `usernameValid` 实时校验，同样处理卡密输入（16 位字符集即时校验 + 推广码 8 位提示），减少一次往返。

**10. 列表页长内容滚动性能（待复核）**
- 现象：好友、日志、活动中心在账号多、记录多时是长列表，浏览器走查因数据为空无法评估滚动性能。
- 建议：数据多时考虑虚拟滚动（Naive UI `n-virtual-list` 或自研窗口化），先量化再动手。

**11. 细节一致性（小项合集）**
- 删除/危险操作的红色在多处使用不同深浅（`text-red-500 / red-600 / dark:text-red-400` 三种），建议统一为一个 Token。
- 弹窗宽度不一致：ConfirmModal 420px、UsersPanel 编辑 440px、AccountModal 另有宽度，统一到 2 档（sm 420 / md 560）。
- 页面切换动效 `page-fade`（0.16s）与弹窗默认动效时长不一致，观感上弹窗偏慢，可统一到 0.16-0.2s。
- 「推广功能面向普通用户」管理员视角空态（浏览器实测确认）建议补一句「普通用户登录后可见」，避免误判为 bug。

### 浏览器实测存疑项（复核后再定）

- 「桌面端概览页出现底部导航」：代码核实 `MobileBottomNav` 为 `lg:hidden`（≥1024px 不渲染），疑似走查时视口宽度不足，**建议人工在 1440px 下复核一次**。
- 「375px 下顶部栏/底部导航横向溢出」：底栏为 5 列 `minmax(0,1fr)` 悬浮胶囊，代码上不应溢出；若复现，多半是某页内容撑破而非导航本身，定位到具体页面再修。

## 三、快速胜利清单（合计约半天）

1. 新增 3 个面板的空状态换 `EmptyState`，无账号空态加「立即添加」按钮。
2. 图标按钮批量补 `aria-label`。
3. 卡密页选中后操作条吸顶。
4. 登录页卡密 16 位即时校验。
5. 概览页无账号引导卡。
6. 管理员视角推广页空态补说明文案。

## 四、建议实施顺序

1. **第一周**：快速胜利清单（1-6）+ 设置页移动端 Tab 收纳。
2. **第二周**：深色 Token 收敛（先新面板后 ConfigManage）+「更多」底部抽屉。
3. **按需**：Settings 拆路由、长列表虚拟滚动（先埋点量化）。
